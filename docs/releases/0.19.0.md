Nineteenth release. The project now requires independent build, security and end-to-end gates on every protected-branch change, and an annotated release tag produces a verifiable image and release artifacts automatically.

## What is new

- Independent GitHub Actions checks cover full Maven verification, workflow lint, all application image builds, CodeQL, dependency review and Trivy image scanning.
- A Compose end-to-end workflow starts the release-shaped image with PostgreSQL metadata and drives a complete SQLite backup, checksum, download, restore verification and cross-target restore through the bundled `dbbackup` CLI and `/api/v1`.
- E2E failure coverage includes JSON authentication failure, a terminal failed backup, corrupted-artifact detection, failed restore verification and preservation of an existing download destination after an HTTP error.
- Weekly Dependabot groups Maven, GitHub Actions and Docker updates against `develop`; every external action is pinned to an immutable commit SHA.
- Annotated release tags publish the base Linux AMD64 image to `ghcr.io/hoangluongtran0309/database-backup-utility` with exact, minor and `latest` tags.
- GitHub Releases now carry executable web and CLI JARs, SHA-256 checksums and SPDX JSON SBOMs. GitHub attestations bind build provenance and SBOMs to both the image digest and JAR digests.
- `SECURITY.md` documents private reporting, supported versions, vulnerability suppression rules and the boundary around operator-built client packs.
- The release baseline moves to Spring Boot 4.1.1, Tomcat 11.0.25 and Docker CLI 29.8.1 so the published base image contains no known fixable high or critical finding at release validation time.

## Behaviour changes

- Both `main` and `develop` accept changes only through merge-commit pull requests after all required CI, security and E2E checks pass. Release and hotfix merge-back therefore use PRs instead of direct pushes.
- Fixable `HIGH` or `CRITICAL` findings in a CI-buildable image fail the container gate. A temporary suppression must be specific, justified and expire within 90 days.
- The SQL Server verification example temporarily suppresses only the affected upstream Microsoft Go binaries; the exception expires on 15 December 2026 and does not apply to the published base image.
- CodeQL uses the Java security-extended query suite. Dependency Review blocks newly introduced dependencies with high or critical known vulnerabilities while reporting, but not enforcing, license information.
- A release tag is rejected unless it is annotated, reachable from `main`, matches the non-snapshot Maven version and has curated notes using the established release-note headings.
- Release publishing is idempotent: rerunning the workflow refreshes the same image tags, release body and assets rather than creating a second release.

## Upgrading from 0.18.0

- No database migration, application configuration change or `/api/v1` contract change is required.
- Container deployments may pull `ghcr.io/hoangluongtran0309/database-backup-utility:0.19.0`; pin its published digest when deterministic rollout is required.
- Operators using source or custom Oracle/SQL Server variants can continue building the supplied Dockerfiles. Scan the final derived image because CI cannot inspect operator-provided Oracle clients.
- Contributors now submit release merge-back through a pull request and must wait for all required checks; the detailed sequence is in `docs/branching.md`.
- Security reports should use the repository's private vulnerability reporting form rather than a public issue.

## Scope and limitations

The automated release publishes only the base Linux AMD64 application image. Oracle and SQL Server application variants and the SQL Server verification image remain operator-built and are not GHCR release products. The new E2E path validates the assembled HTTP API/CLI deployment with SQLite; the existing real-container integration suite remains responsible for the seven database engines and cloud-storage adapters. This release does not add browser automation, image signing keys, deployment promotion environments or runtime application features.

## Verification

- Feature, release, release-PR and merge-back PR workflows run full Maven verification with every required database client installed and no self-skipping integration test.
- CI builds and smoke-tests the base, Oracle example, SQL Server application and SQL Server verification images, then scans every buildable image for fixable high and critical findings.
- CodeQL, Dependency Review, actionlint/ShellCheck and the Compose API/CLI E2E path are independent required checks.
- The tag workflow verifies release checksums, publishes SPDX SBOMs and records GitHub provenance and SBOM attestations for the GHCR digest and both executable JARs.
